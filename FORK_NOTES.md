## 1. Цель форка

Главное отличие форка от оригинала — **формат вывода для `SBER_PAYMENT_DEBIT_2604b`**.
Вместо стандартного набора колонок форк выдаёт ровно **5 колонок**:

| Дата операции | Дата учёта | Приход | Расход | Имя |
|---------------|------------|--------|--------|-----|
| `06.09.2026`  | `06.09.2026`| `47200` |        |     |
| `06.09.2026`  | `06.09.2026`|        | `105`  | `Анна Павловна К.` |

Правила:
- **Даты** — строки `dd.mm.yyyy` (не `datetime`). `Дата учёта` всегда равна `Дата операции`.
- **Приход / Расход** — целые числа. Копейки округляются до целого (`ROUND_HALF_UP`),
  например `104,78` → `105`. Знак определяет вид: приход `+...`, расход без знака.
- **Имя** — контрагент из описания операции, переставлен в формат `Имя Отчество И.`
  (исходно в выписке `И. Имя Отчество`).

Остальные форматы выписок — как в оригинале.

## 2. Структура git-репозитория

- `origin` (форк) = `https://github.com/sankarsana/Sberbank2Excel.git` — мой аккаунт.
- `upstream` (оригинал) = `https://github.com/Ev2geny/Sberbank2Excel.git` — репозиторий автора.
- Default-ветка (HEAD) = `master`. Работа ведётся в feature-ветках.

## 3. Обновление приложения

Работа ведётся на **двух компьютерах**:
- **Dev-комп** — здесь меняется код, есть AI-агент, git-репозиторий.
- **Рабочий комп** — здесь только запускается приложение (без AI). Установлено через `uv tool install`.

### Dev-комп (правлю код)

Перед началом новой задачи синхронизировать `master` с оригиналом:

```bash
git switch master
git fetch upstream
git merge upstream/master   # влить изменения автора; при конфликтах — решить вручную
git push origin master
```

Новую работу вести в feature-ветках от актуального `master`:

```bash
git switch -c feature/<описание>
# ... правки ...
git commit
git push -u origin feature/<описание>
```

После проверки смержить feature-ветку в `master` и запушить форк:

```bash
git switch master
git merge feature/<описание>
git push origin master
```

### Рабочий комп (запуск приложения)

Приложение установлено **из форка** (не из оригинала), чтобы получать и свои правки,
и новые экстракторы автора.

Проверить установленную версию:

```
uv tool list
```

Первичная установка / переустановка **из форка** (меняет источник на форк):

```
uv tool install git+https://github.com/sankarsana/Sberbank2Excel.git --force
```

Обновление до последней версии форка:

```
uv tool upgrade sberbank2Excel --force
```

`--force` обязателен: `uv tool upgrade` сравнивает версию из `pyproject.toml` и не
подтянет изменения, если номер версии не изменился.

## 4. Команды для рабочего компа (полный блок)

Весь сценарий на рабочем компе — от переустановки источника до проверки:

```bash
# 1. Убедиться, что источник — форк (после этого навсегда тянет из форка)
uv tool install git+https://github.com/sankarsana/Sberbank2Excel.git --force

# 2. (Далее) обновлять до последней версии форка
uv tool upgrade sberbank2Excel --force

# 3. Проверить установленную версию
uv tool list

# 4. Проверить, что приложение работает
sberbank2Excel -h
```
